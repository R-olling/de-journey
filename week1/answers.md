# 六问（每问一句结论 + 一个数字）

## Q1 每月均值

24 个月请求量稳定在 **1,166–1,583 条/月**、没有增长趋势，波动主要来自处理时长（中位时长 2024-04 最高 82.2 h、2025-12 最低 57.0 h）而非单量。

## Q2 缺失率最高的三列

只有两列有缺失：`citizen_rating` **65.44%**（20,809 行）和 `closed_at` **0.74%**（236 行），一个保留 NaN、一个过滤删行，**两列都不该填**。

## Q3 按类别分组后的 Top10

前三名全是 `road_damage`（**54.1% / 53.1% / 52.6%**），三个优先级同时超时 → 类别级的系统性超时，解法是重定 SLA 或加派工，不是优先级排错。

## Q4 两表 merge 后行数为什么变了

行数只可能因为三件事变：键重复会爆炸（**31,801 → 44,246**）、键对不上会丢行（inner：**31,801 → 31,165**）、基表口径变会整体位移；这次 `districts` 是干净唯一键，所以 **31,801 → 31,801** 一行没少。

## Q5 派生指标的分布

`hours` 从 **0.28 h** 到 **2,826.08 h**（p50 72.26 / p99 852.27），超 p99 的 **316 条**保留：负时长是录入错误要删，118 天是真实事件要留并单列观察。

## Q6 导出清洗后的结果

csv **4,583 KB** 读回 `closed_at` 是 `str`、parquet **1,089 KB** 读回是 `datetime64[us]`；csv 是交换格式、parquet 是存储格式，两份都留。
