# 闭卷小测 · 单元 4（5 题）

> 规则：先自己写，写完再对下面的答案键。判分：每题 1 分，≥3 分过关，<3 分要回头重讲"退出码"和"三层防线"。
> 全部基于本机实测（2026-11-22，656 行 / 14 条校验 / 6 次运行）。

---

## 题

**1.** 07:00 触发时 Docker Desktop 没起（daemon 未运行），会发生什么？退出码几？日志第一行是什么？数据库会变吗？`ops.pipeline_run` 会多一行吗？

**2.** 如果把窗口改成 `--start 2026-12-28 --end 2027-01-03`：哪一条校验会先红？它报什么？如果绕过它直接跑 load，会在哪里失败、报什么错？

**3.** 把 `--lookback` 从 7 改成 1：14 条校验里哪几条会红？哪几条不会？"回填窗口"发生了什么变化？

**4.** 上游把某个城市这 7 天里的 2 天数据漏了（其他城市正常）。哪几条校验会红？"行数突变"会不会红？为什么？

**5.** 同一窗口连跑两次：`ops.pipeline_run` 会有几行？`mart.fact_weather_daily` 行数会变吗？为什么这不算 bug？

---

## 我的答案（自测）

**1.** `preflight()` 里 `docker info` 抛 `CalledProcessError` → `EnvError("Docker daemon 没起...")` → 日志 `ERROR ENV Docker daemon 没起 ...` → **退出码 2**。数据库**完全不变**，因为还没 `connect()`；`ops.pipeline_run` **也不会多一行**，因为 INSERT 发生在连库之后。计划任务的 `LastTaskResult` 会是 `0x2`。

**2.** `pre` 的第 8 条「窗口在 dim_date 覆盖内」先红，detail 是 `窗口 2026-12-28~2027-01-03，日历 2026-01-01~2026-12-31`，exit 1、不写库。绕过它跑 load：`ERROR: insert or update on table "fact_weather_daily" violates foreign key constraint "fact_weather_daily_date_key_fkey"`，`DETAIL: Key (date_key)=(2027-01-01) is not present in table "dim_date"`。

**3.** **都不红**。1 天窗口时：`pre` 的日期覆盖成立、行数 = 8×1 = 8 成立；`post` 覆盖率按 1 天算 8/8 成立；新鲜度不变（还是昨天）；行数突变不算红——它比的是"每城每天"，1 天窗口仍是 8.0 行/天，偏离 0%。变化在**回填窗口从 7 天缩到 1 天**：11/18 的修订不会再有机会被覆盖。

**4.** `pre` 的「行数 = 城市数 × 天数」红（8×7 − 2 = 54 ≠ 56）；`post` 的「窗口覆盖率」红（那个城市只有 5 天，`full` 变成 7/8）。「行数突变」**不会红**：54/7 = 7.71 行/天 vs 8.0，偏离 3.6%，远小于 50%。阈值 50% 的定位是"抓大崩"，不是"抓少 2 行"。

**5.** `ops.pipeline_run` **2 行**（每次运行一行，`rows_loaded` 都是 56）；`fact` 仍是 **656**。不算 bug：`ops` 记的是**运行**（运维事实），`fact` 记的是**数据**（业务事实）。同一份数据被覆盖两次，正是幂等该有的样子。

## 答案键

| 题 | 答案 | 判分点 |
|---|---|---|
| 1 | 退出码 **2**；日志 `ERROR ENV Docker daemon 没起：...`；库**不变**；`ops` **无新行** | 必须说出"2"和"库不变"；说出"ops 也没记录"加分 |
| 2 | **「窗口在 dim_date 覆盖内」先红**，detail 含 `2026-01-01~2026-12-31`；绕过则 `violates foreign key constraint "fact_weather_daily_date_key_fkey"`，`Key (date_key)=(2027-01-01)` | 必须说出"日历维覆盖"这条 + FK 报错关键词 |
| 3 | **都不红**；变化是**回填窗口 7 天 → 1 天** | 只答"红/不红"不给分，必须说清回填窗口变窄 |
| 4 | pre 的行数校验红、post 的覆盖率红；**突变不红**（7.71 vs 8.0，3.6%） | 必须说出"突变不红"和"50% 抓的是大崩" |
| 5 | `ops` **2 行**、`fact` **656**；理由是"运行 vs 数据"的分工 | 必须说出"2 行" |
