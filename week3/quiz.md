## 答案键（答完再往下滚）

| 题 | 答案 | 判分点 |
|---|---|---|
| 1 | 抽取和 `transform` **都正常**（600 行），失败在 `load` 的 upsert：`ERROR: insert or update on table "fact_weather_daily" violates foreign key constraint "fact_weather_daily_date_key_fkey"`，`DETAIL: Key (date_key)=(2026-09-01) is not present in table "dim_date"`。**一条都进不去** | 说出"错在外键、不在抽取"，并指出 `dim_date` 是 2024–2025 |
| 2 | **80 行**；只有 **`行数 = 城市数 x 天数`** 会红（79 ≠ 80）。**`日期覆盖 = 请求区间` 不会红**——其他 7 个城市都有那一天，`nunique` 仍是 10。第一条查"整体覆盖"，第二条才查"每城数量"，**两条必须成对看** | 说出"只有一条红"+"为什么第一条不红" |
| 3 | 窗口从 7 天变 **8 天**；**64 行**参与聚合（8 城 × 8 天）；北京从 **10.30** 变 **9.90**（武汉 4.86 → 4.84） | 8 天 + 64 行 + 10.30→9.90 |
| 4 | 从 **4 个**变 **7 个**（Marseille 8 / Lyon 7 / Toulouse 5 / Shanghai 4 / Wuhan 4 / Chengdu 3 / Paris 3）。**不能说多出来的错**——0.1mm 是"有降水（含毛毛雨）"，1.0mm 是"真下雨"，两个都是有效口径，区别只在定义 | 说出"阈值是口径选择，不是对错" |
| 5 | psycopg 把 `float('nan')` 发成 `numeric 'NaN'`，Postgres 的 `numeric` **接受 NaN 且不等于 NULL**，于是 `count(列)` 把它算作非空、`avg()` 结果变 NaN，全链路不报错。防住它的是 `load.py` 的 `to_rows()`：`pd.isna(value) → None` | 说出"NaN ≠ NULL"和 `to_rows` |
